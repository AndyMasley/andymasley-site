Phase VI · authored

Agent architecture and reliability

Read

  • AgentDojo (Debenedetti et al., NeurIPS 2024, arXiv:2406.13352) — the threat model (§3.3, indirect injection via tool outputs), the attack taxonomy, then the defenses (§4.3). Write an evidence brief on the claim that no current defense reaches high utility and high security at once.
  • Simon Willison, prompt-injection series (series) — "The lethal trifecta for AI agents" (16 June 2025) and "Delimiters won't save you from prompt injection" (2023). Grade "avoid the trifecta entirely" as advice for a deployer who cannot avoid it.
  • Defeating Prompt Injections by Design (CaMeL) (Debenedetti et al., Google DeepMind, 2025, arXiv:2503.18813) — optional. The capabilities-based defense your privilege-separation option is a toy of. Keep a ledger of what "provable" buys that a low attack-success rate does not.
  • OWASP Top 10 for LLM Applications 2025 (genai.owasp.org) — optional, skim. LLM01 Prompt Injection, LLM06 Excessive Agency, LLM02 Sensitive Information Disclosure. Map your build's attack path onto its entry IDs.

Do

  1. Weaponize the injection. Reread your W30 build and repair it if it no longer runs. Escalate the planted-file instruction into an attack with a security consequence: exfiltrate a second file's contents into the answer, invoke a tool the user never requested, or return an attacker-chosen result while claiming it is the user's. Run it and capture the full transcript.
  2. Add exactly one defense, for real. Tool-call approval: a human confirms each call before it runs. Input marking: wrap tool-returned strings in delimiters and tell the model they are data. Privilege separation: a planner LLM that issues tool calls but never sees raw tool output, plus a quarantined LLM that reads untrusted content and holds no tools.
  3. Run three times, commit all three. Benign task with the defense on; adversarial task with it off (injection succeeds); adversarial task with it on (injection blocked). If you chose input marking, adapt the injection to break out of your delimiters first, predicting whether it holds.

The artifact is the harness plus a one-page deployment memo. The harness runs the benign and adversarial tasks under both defense states, with an append-only log per run. The memo, addressed to a named principal deciding whether to point this agent at untrusted content, states the confused-deputy threat in three plain sentences, names the defense you built and what class of attack it does and does not stop, cites the AgentDojo frontier as the reason no single control suffices, and gives a go/no-go with permission and oversight conditions attached. Close with one line on what the harness cannot establish.

Done when all three runs are committed and the repo shows the injection succeeding in the undefended adversarial run and failing in the defended one, with the benign run's task output unchanged by the defense. If the defense breaks the benign task or fails to block the attack, the memo says which and why; a documented failure of a named defense passes, an undocumented one does not.

Skip if you can already show a committed adversarial transcript where an injection hijacks an agent you built, plus a second transcript where one named defense blocks the same injection without breaking a benign task.

Take away

  • Prompt injection is a confused-deputy failure: a privileged program tricked into misusing its authority for someone who lacks it. Your agent holds your tool permissions, attacker-controlled content enters the same context window, and the model has no reliable boundary between instruction and data.
  • "Tell the model to ignore instructions in the content it reads" is not a permission system. It is a filter, and a filter that stops 99% of injections is a failing grade against an attacker with unlimited attempts. Delimiters and system prompts move probabilities, not permissions.
  • The boundary a confused deputy needs is structural and enforced outside the model, which is what makes it indifferent to how persuasive the injected text is. Name it as an authority-separation problem and the defenses sort themselves into ones that could work and ones that can't.
  • No defense holds both ends. On GPT-4o, AgentDojo reports ~69% benign utility against ~61% targeted success for the adaptive attack; the injection detector cuts attack success to ~8% but benign utility to ~41%, and the tool filter reaches ~7% only where it applies.
  • Isolation has a hard floor: for ~17% of AgentDojo's test cases the tools needed to do the task are sufficient to carry out the attack.
  • The dominant reliability failure in deployed agents is a correctly executed action taken on the wrong party's orders. W32 measures the reliability you are defending, W41 catalogs the misuse this enables, W43 builds monitoring that assumes injection is unsolved.
  • Policy: NIST's Center for AI Standards and Innovation issued a Request for Information Regarding Security Considerations for Artificial Intelligence Agents (docket NIST-2025-0035, Federal Register, 8 January 2026; comment period closed 9 March 2026 with 932 comments), and the CAISI AI Agent Standards Initiative (launched 17 February 2026) carries it forward.
  • The RFI's five headings are threat identification, lifecycle security, cybersecurity-framework gaps, security measurement, and environmental controls. Your build answers three in miniature. Write the comment you would file and diff your lever, evidence, and ask against the filed ones on regulations.gov.
Check yourself
  1. Define a confused deputy, then say in one sentence why prompt injection is an instance. Whose authority is spent, and whose instruction is followed?
  2. A vendor's guardrail blocks 99% of injection attempts in testing. Give the security-specific reason this is a failing grade.
  3. AgentDojo's tool-filter defense cuts attack success to roughly 7%, but the paper names a case where isolation cannot help at all. What is it, and for what fraction of test cases does it hold?
  4. Name the three legs of the lethal trifecta. A deployer removes the agent's ability to make outbound network calls but keeps the other two. Is the trifecta defused, and why? Then say what CaMeL's 77%-with-provable-security versus 84%-undefended buys and costs relative to an ~8%-attack-success detector.

Answers. (1) A confused deputy is a privileged program tricked into misusing its authority for a party that lacks it. Injection qualifies because the agent holds the user's tool permissions while attacker-controlled content sits in the same context with no enforced boundary between principal-instruction and data-to-process. Your authority is spent; the attacker's instruction is followed. (2) Security is adversarial and the attacker has unlimited attempts, so a 99% filter means one try in a hundred succeeds and the attacker retries until it does. A control that moves the probability of success without bounding it doesn't hold, which is why the boundary has to be structural rather than statistical. (3) When the tools required to complete the legitimate task are themselves sufficient to carry out the attack, isolation can't remove a capability the task needs; AgentDojo reports this for ~17% of its test cases. (4) Access to private data, exposure to untrusted content, and the ability to communicate externally. Removing outbound communication defuses the trifecta for exfiltration: the attacker can still hijack the agent but has no channel to send stolen data out, and removing any one leg breaks the specific chain, since the hazard is the combination. A capabilities defense enforces the boundary outside the model, so untrusted data cannot alter the trusted control flow and tool access is gated by a policy the model can't talk its way past, which is what makes the security provable rather than probabilistic. It cost 7 points of utility, 77% against 84% undefended.
